# Contributing to SendStack

Welcome — and thanks for investing time in SendStack. This guide gets you from zero to a running local environment, then covers everything you need to contribute code, docs, or bug reports.

---

## Prerequisites

| Tool | Minimum version | Install |
|---|---|---|
| Docker Desktop | 24.0+ | [docs.docker.com](https://docs.docker.com/get-docker/) |
| DDEV | 1.22+ | [ddev.readthedocs.io](https://ddev.readthedocs.io/en/stable/) |
| Git | 2.30+ | [git-scm.com](https://git-scm.com/) |
| Composer | 2.x | [getcomposer.org](https://getcomposer.org/) |
| Node.js | 20 LTS | [nodejs.org](https://nodejs.org/) |
| Python | 3.8+ | [python.org](https://python.org/) — needed for pre-commit |
| GNU Make | 3.81+ | Pre-installed on macOS/Linux; WSL2 on Windows |

---

## ⚠️ Windows users — read this first

All commands in this guide **must run inside WSL2** — not PowerShell, not Command Prompt.

1. [Install WSL2](https://learn.microsoft.com/en-us/windows/wsl/install) (Ubuntu 22.04 recommended)
2. Install Docker Desktop, and in Docker Desktop settings → Resources → WSL Integration, enable your WSL2 distro
3. Open a WSL2 terminal and install DDEV [using the Linux instructions](https://ddev.readthedocs.io/en/stable/users/install/ddev-installation/#linux)
4. All `make` commands below run from within WSL2

## Quick start

```bash
# 1. Clone
git clone https://github.com/x1techs/sendstack.git
cd sendstack

# 2. Copy env file (defaults work with DDEV — edit only if you need overrides)
cp .env.example .env

# 3. Build the environment
make setup
```

When `make setup` completes, you have:

- WordPress running at **https://sendstack.ddev.site**
- Admin at **https://sendstack.ddev.site/wp-admin/** (user: `admin` / pass: `admin`)
- Mailpit email UI at **https://sendstack.ddev.site:8026**

---

## What `make setup` does

- Starts DDEV (pulls Docker images on first run — takes ~2 min once)
- Runs `.ddev/wp-setup.sh` inside the container:
  - Downloads WordPress core into `wordpress/` (gitignored)
  - Creates `wp-config.php` with debug constants enabled
  - Installs and configures WordPress
  - Installs testing plugins (Query Monitor, WooCommerce, CF7, etc.) — inactive by default
  - Installs Twenty Twenty-Four and Kadence themes
- Installs Composer dev dependencies (once `composer.json` exists)
- Installs Node dependencies (once `package.json` exists)
- Installs pre-commit git hooks (if Python/pre-commit available)

The setup is **idempotent** — safe to run again; it skips steps already completed.

---

## The `wordpress/` directory

`wordpress/` is gitignored. It is auto-generated by `make setup` and can be deleted and rebuilt at any time with `make reset`. Never commit anything inside it.

## Daily workflow

```bash
make up        # start the environment
# ... do your work ...
make test      # run tests before committing
make lint      # check coding standards
git add -p     # stage changes
git commit     # pre-commit hooks run here
git push
```

## Branching

| Branch | Purpose |
|---|---|
| `main` | Latest stable release — never commit directly |
| `develop` | Integration branch — PRs merge here first |
| `feature/*` | New features — branch from `develop` |
| `fix/*` | Bug fixes — branch from `develop` |
| `hotfix/*` | Urgent production fixes — branch from `main`, PR back to both `main` and `develop` |

```bash
git checkout develop
git pull origin develop
git checkout -b feature/your-feature-name
```

## Commit messages

We use [Conventional Commits](https://www.conventionalcommits.org/).

Format: `type(scope): description`

| Type | When to use | Example |
|---|---|---|
| `feat` | New user-facing feature | `feat(mailer): add SendGrid retry on 5xx` |
| `fix` | Bug fix | `fix(smtp): handle connection timeout gracefully` |
| `chore` | Tooling, deps, config | `chore(deps): update phpunit to 10.x` |
| `docs` | Documentation only | `docs(onboarding): add xdebug PhpStorm steps` |
| `refactor` | Code restructure, no behaviour change | `refactor(core): extract ProviderFactory from Plugin` |
| `test` | Tests only | `test(mailer): add unit tests for GmailProvider` |
| `ci` | CI workflow changes | `ci: add PHP 8.2 to matrix` |
| `style` | Formatting (PHPCS auto-fix commits) | `style: apply phpcbf fixes` |
| `perf` | Performance improvement | `perf(log): batch DB writes for delivery log` |

Use the imperative mood in the description: "add", not "adds" or "added".

## Pull request process

Before opening a PR:

- [ ] `make test` passes locally
- [ ] `make lint` passes (or `make fix` applied and committed)
- [ ] `CHANGELOG.md` updated under `[Unreleased]`
- [ ] Docs updated if you changed behaviour or added a hook/filter
- [ ] Screenshots attached for any UI changes
- [ ] PR title follows Conventional Commits format

PRs go to `develop` unless it is a hotfix (then `main`). One approving review required; CI must pass.

## Running tests

```bash
make test               # all tests
make test-unit          # PHPUnit unit tests only
make test-integration   # PHPUnit integration tests (requires live DDEV WP)
```

---

## Linting and static analysis

```bash
make lint    # PHPCS (WordPress Coding Standards) + PHPStan (level 5)
make fix     # Auto-fix PHPCS violations with phpcbf
```

Standard: [WordPress Coding Standards](https://developer.wordpress.org/coding-standards/wordpress-coding-standards/php/) via PHPCS. PHPStan at level 5.

---

## Pre-commit hooks

```bash
make hooks   # install hooks (run once after cloning)
```

On every `git commit`, pre-commit runs PHPCS on staged PHP files and standard checks (trailing whitespace, file endings). PHPStan is intentionally excluded — it is too slow for interactive use and runs in CI instead.

To skip hooks in an emergency: `git commit --no-verify` (use sparingly; CI will still catch violations).

## WordPress.org compliance

SendStack is a free plugin on the WordPress.org Plugin Directory. Every contribution must:

- Use a GPL-compatible license for any included code
- Never mention competitor plugins by name (WordPress.org policy)
- Never add upsells, premium-feature prompts, or rate-nag screens
- Never bundle third-party libraries without namespacing via PHP-Scoper
- Sanitize all input, escape all output, verify all nonces

When in doubt, check the [Plugin Review Guidelines](https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/).
